# The runtime

The runtime as Maxon source: one module, compiled with every program that `self/` builds. The design (how a compile
finds this directory, the `__Raw` intrinsics, how an entry the compiler calls maps to a function here, the globals) is
the root README's section "The runtime". `minimaxon check runtime` checks it, and `.\check.ps1` runs that.

| File | Entries the compiler calls | Holds |
|---|---|---|
| `layout_gen.maxon` | — | generated by `internal/abigen` from the ABI layouts table: the word, the string, array and byte array boxes, the empty box, a frozen value's box, a cown, a behaviour's record and its request slots, a thread's context |
| `heap.maxon` | `alloc`, `free` | a heap per thread: boxes in size classes carved from chunks of the process heap, a large box a block of its own, the list of a heap's boxes that other threads freed, the count of live boxes summed over the heaps, and the blocks the runtime keeps for the life of the process |
| `output.maxon` | `write`, `panicWith`, `panicIndex`, `checkLeaks` | writing to a handle, panics, the leak report |
| `strings.maxon` | `concat`, `itoa`, `streq`, `stringLength`, `stringByteAt`, `stringSlice` | the string entries |
| `arrays.maxon` | `arrayNew`, `arrayLength`, `arrayElem`, `arrayInsert`, `arrayRemove`, `arrayShrink` | the array entries, and the routines that arrays and byte arrays share, which take an element's size |
| `bytes.maxon` | `bytesNew`, `bytesLength`, `bytesGet`, `bytesSet`, `bytesInsert`, `bytesRemove`, `bytesAppend`, `bytesAppendStr`, `bytesToString` | the byte array entries |
| `textops.maxon` | `stringCount`, `stringGraphemeIndex`, `stringGraphemeBytePos`, `stringFind`, `stringFindLast`, `stringHasAffix`, `stringReplace`, `stringTrim`, `stringMapCase`, `stringCodePointAt`, `stringCodePointNext`, `stringCodePointCount`, `stringUtf16Unit`, `stringUtf16Next`, `stringUtf16Count` | the String methods that read more than a byte: grapheme clusters, search, replace, trim, case. The interpreter runs the same text, which `builtingen` copies to `self/interp/textops_gen.maxon`, so it uses only what both modules have (a String's byte methods, interpolation, integers) and no `__Raw` |
| `floats.maxon` | `ftoa` | the text of a double, from its bits, with big integers in a scratch box |
| `unicode_gen.maxon` | — | generated by `internal/textgen` from the Unicode data: the grapheme cluster classes and the table of them that `textops.maxon` searches |
| `text.maxon` | — | UTF-8 and UTF-16 conversion, over addresses and lengths, for the `W` calls |
| `commandline.maxon` | — | the C runtime's command-line splitter and the quoting that is its inverse |
| `os.maxon` | `osArgs`, `osEnvironmentVariable`, `osPathFrom`, `osReadText`, `osWriteText`, `osWriteBinary`, `osRename`, `osDelete`, `osIsDirectory`, `osCreateDirectory`, `osList` | files, directories, paths and the environment, over the `W` Win32 calls |
| `subprocess.maxon` | `osRun` | `CreateProcessW` with the child's output and error read through pipes |
| `frozen.maxon` | `frozenFreeze`, `frozenGet`, `share`, `cownNew` | making a frozen value and a cown, and another owner of one, a locked add on the count; the backend writes `frozenGet` in place, and a drop is the routine of the type, which `self/backend` makes (README, "Frozen values, cowns and behaviours in the IR") |
| `sched.maxon` | `schedDrain`, `workerMain`, `osSetExitCode` | the scheduler: the workers, their Chase-Lev queues, stealing, parking and waking, the count of live behaviours, and the exit code. `cownAcquire` calls `schedEnter` for each behaviour, before it can run, and `schedPush` with its record when it is runnable, as `cownRelease` does for the behaviour it hands a cown to |
| `cown.maxon` | `cownAcquire`, `cownRelease` | behaviours on cowns: the acquire that a compiled `when` calls with the behaviour's record (the slots sorted by cown address, the trap on a cown named twice, the behaviour's hold on each cown, and Verona's two-phase queuing on each cown's chain of request slots), and the release that a behaviour's thunk calls after its body, which hands each cown to the behaviour queued after it; the thunk then drops the holds, since only the compiled code knows the cowns' types |

## Rules a runtime file follows

- **Only the runtime calls `__Raw`.** Anywhere else a call of one is `E3152`.
- **An entry the compiler calls has the table's signature** (`runtimeFunctions` in `internal/builtingen/table.go`):
  words only (`Count`, `Byte`, `bool`, `String` as its box address), no `mutates`, no type parameter, no `throws`.
  `check runtime` refuses a missing one (`E3004`) and a different one (`E3005`). A new entry is a row of `entries` and
  of `runtimeFunctions`, then `go generate ./internal/...`, then its function here.
- **The same code for every build.** The runtime reads no build option: what an option changes is the entry stub's
  (`self/backend/entry.maxon`), as `--count-allocations` makes the stub call `checkLeaks`.
- **No primitives and no throwing.** The runtime implements `Array`, `Map` and the rest, so it uses none of them; a
  failure it cannot pass on is a `panic`, whose message is a literal, or `exitProcess`.
- **A layout is a named constant of `layout_gen.maxon`** (the table is `internal/abigen/table.go`), never a number in the code that reads the box.
- **Behaviour is maxon's runtime's**: the same messages, exit codes and Win32 calls, until a change is recorded in the
  root README's "Where it differs from Maxon".
- **A test of the runtime** is a program of `tests/runtime/`, which the test runner compiles as one more file of this
  module, so that it may call what no program can (root README, "Tests"). Its names start with `test` or `tally`, so
  as not to clash with the runtime's own.
- **A DLL function is called by its name**, a string literal, which must be in the executable's import list
  (`importNames` in `internal/abigen/imports.go`, which generates `self/backend/imports_gen.maxon`); `self/backend` panics on one that is not.
