# Porting a package into `self/`

`self/` is minimaxon ported to Maxon, compiled by the Go compiler until it compiles itself (plan Stage 1.5). The Go
compiler implements only what `self/` needs; once `self/` self-hosts, compiler work in Go ends (`cmd/convert` and
`internal/grammargen` stay Go tools until the cutover). The plan is

for the step you are on.

## 1. Before porting: does maxon already have it?

- Look in `c:\Users\Eric\Dev\maxon\maxon-bin\` and `maxon\stdlib\` for code doing the same job. Plan "Reuse" names the

- If it fits `self/`'s architecture, convert it with `cmd/convert` (skill `convert-from-maxon`). Converted files are
  regenerated, never hand-edited.
- If it does not fit, or needs a feature minimaxon lacks, it is still the reference: follow its behaviour, edge cases
  and names unless README "Where it differs from Maxon" records a deliberate change.
- Search maxon's big files (`Parser*.maxon` ~600 KB, `docs/LANGUAGE_REFERENCE.md` ~420 KB) with Grep and line ranges.

## 2. Order and what a port matches

Bottom-up, one step at a time; a package uses only the ones above it.

| Step | `self/` | Mirrors | State |
|---:|---|---|---|
| 1 | `diag/` + `table/` | `internal/diag`, hash maps on `array` | exists |
| 2 | `ast/` | `internal/ast` | exists |
| 3 | `syntax/` | `internal/syntax` | hand lexer and parser; generated DFA and parser planned (1.3) |
| 4 | `project/` | `internal/project` | exists |
| 5 | `resolve/` | `internal/resolve` | exists |
| 6 | `check/` | `internal/check` | started (`context.maxon`) |
| 7 | `ir/` | `internal/ir` | planned; the IR generator comes first |
| 8 | `backend/` + `runtime/` | `internal/backend` | planned; x64 encoder and ABI layout generators first |
| 9 | `driver/` + `main.maxon` | `internal/driver`, `main.go` | planned |

A port matches the Go package's behaviour, diagnostics (code, position, message) and the program's output. It need
not match bytes: byte-identical output is never a goal. Read the Go file and port its structure (same phases, same
function split, names in Maxon's casing), so a later diff of the two stays readable.

## 3. Go to Maxon

Follow what `self/` does now; the README sections "The subset", "Ownership", "Generics", "Primitives" and "Where it
differs from Maxon" are the rules.

| Go | `self/` |
|---|---|
| struct | `export type` with `export var` fields and a `static function make(...)` or `new()` returning `Self{...}` (`self/ast/tree.maxon`) |
| slice | `array with T`, named by a typealias (`typealias Counts = array with Count`); flat records indexed by handles, as `ast.Tree`'s 16-byte `Record` |
| `map` | `table.StringMap with V` / `table.IntMap with V` (`self/table/map.maxon`), until `stdlib/Map.maxon` converts. Never the built-in `map`, `list` or `pool`, nor `frozen`/`cown`/`when`: they have no native code (`E9900`) |
| interface over a closed set | `union` with payload cases and methods that `match self` (`ast.Decl` in `self/ast/decls.maxon`) |
| type switch over AST nodes | a visitor generated by `internal/grammargen` (planned, 1.3); until it exists, an `if k == ast.NodeKind.x` chain that ends in `panic` (`self/resolve/resolve.maxon`) |
| pointer to a shared thing | a handle: `ast.FuncID`, `ast.TypeID`, `ast.NodeID`, `diag.ModuleID`, an index into a table the owner holds |
| `panic(*diag.CompileError)` | append to a `mutates errs diag.ErrorList` with `diag.pushSiteError` (or `check.checkFail`) and return |
| `(T, error)` / fallible return | a result union (`LexResult`, `ParseResult`: `ok(...)` / `err(...)`) or `table.Option with T` (self's own, `self/table/option.maxon`: nothing is built in), taken with `match consumes` |
| `diag.Internal` panic | `panic("what broke")`, also as `try ... otherwise panic("...")` on a cast that cannot fail |
| integer types | typealiased ranges (`diag.U32`, `ast.U16`); arithmetic that can fail takes `try`, `try x as T otherwise ...` |

`throws`, error enums and maxon's built-in names (`Array`, `push`, `contains`, `File.readText`, no built-in `Option`)
land in Stage 1.2a; that stage's tool rewrites `self/` with `tests/`, so until then write the current names.

## 4. Ownership that compiles

- One owner per value. Shared state is passed down, never held: `mutates p ast.Project, mutates errs diag.ErrorList`.
- Store a value with `consumes` and pass a fresh value or `.copy()`; strings and records into constructors are
  `consumes` parameters.
- Take an owned value out of a field or element with `exchange(place, value: fresh)` (`check.checkerStartMod`), out
  of a union or `Option` with `match consumes`.
- A `consumes` parameter is not mutable: `var mc = c` first.
- `a[i]` borrows: bind a scalar freely (`let n = a[i]`), `.copy()` anything else, assign through `a[i] = v`.
- Exclusivity (`E3186`): an argument passed `mutates`/`consumes`/`sets` may not overlap another argument, and
  `a[i]` overlaps `a[j]`. Read the index or the scalar into a local before the call.
- A borrowed place is held while later operands are evaluated: compute the call that changes it into a local first.
- `sets` for out-parameters; `var x as T` for a value assigned later.
- Every block carries a label (`if c 'name'` ... `end 'name'`); labelled arguments after the first.

## 5. Rules from the plan

- **Runtime is Maxon source** in `self/runtime/` (planned, step 8), compiled and cached with every program. The
  intrinsics (raw load and store, address arithmetic, DLL import calls) are legal only there. Only drop and copy
  routines and the entry stub are compiler-emitted.
- **Collections over layout descriptors:** runtime arrays, maps and lists take a descriptor of the element's size and
  layout; only thin typed wrappers are per type. Packed arrays need one set of routines.
- **One instance per project:** a project-wide instance table keyed by type arguments, claimed once; the claimer
  lowers it, others reference its symbol. Drop and copy routines are made the same way during generate.
- **`self/driver` is a sequential executor over the task graph** (`internal/par/tasks.go`'s `Plan`), keeping the
  per-module scheduling, so Phase 3 swaps the executor, not the driver.
- **Generated parts come from the generators, never by hand:** `self/ast/nodes_gen.maxon` from `Maxon.g4`
  (`go generate ./internal/syntax`); planned: `self/syntax/tokens_gen.maxon` and `parser_gen.maxon` (1.3), built-ins
  and diagnostics tables (1.2a), IR records and printer, x64 encoder, ABI layouts (1.4). A generator that is missing is
  written first, as plain Go, with a test that regenerates and diffs.
- No speed work before Phase 3; act only on an algorithmic blow-up. Data stays flat and handle-indexed.

## 6. Gate and testing

- The step's milestone in plan Stage 1.4. Step 6: every `tests/errors/` case reports its expected diagnostics.
  Step 8: every native `tests/run/` program passes with 0 leaks, and a `self/runtime/` change is picked up by the next
  `C1.exe test` with no rebuild. Those two are measured through `self/driver` (step 9, Stage 1.5's `C1.exe`).
- Until then, `self/main.maxon` is the harness (`testResolve` runs the port over `self`; `main` calls it and prints
  `self: all checks passed`). Add a `test...` function only when a bug would come back or nothing covers the feature.
- Neither test suite compiles `self/`, so run these explicitly (from the repository root):

  ```powershell
  go build -o minimaxon.exe . ; .\minimaxon.exe check self ; .\minimaxon.exe run self ; .\minimaxon.exe fmt --check self
  ```

  `run self` prints `self: all checks passed` and exits 0. `.\minimaxon.exe fmt self` fixes the layout. Building `C1`
  (`minimaxon.exe build self -o C1.exe`) is Stage 1.5.
- Before a commit: `go build`, `go vet ./...`, `gofmt -l .` empty, `go test ./...`, `.\minimaxon.exe test` (or
  `.\check.ps1`). Do not commit unless asked; then directly on `main`.
- A gap in the Go compiler that blocks a port is fixed in Go only if `self/` needs it; a language change goes through
  the `language-change` skill and README "Where it differs from Maxon".
